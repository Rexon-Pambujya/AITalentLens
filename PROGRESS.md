## Known issues / follow-ups

- `EMBEDDING_DIMENSIONS` is hardcoded to 1536 (OpenAI text-embedding-3-small)
  in the initial migration. If you switch to a local embedding model with a
  different dimensionality (e.g. Ollama's nomic-embed-text = 768), you'll
  need a migration to alter the vector column dimension before ingesting
  data with that model.
- Resume repository's duplicate check is exact-hash only; near-duplicate
  (normalized-text-hash, cross-format) and semantic-similarity duplicate
  detection are designed for (see `normalized_text_hash` in
  `app/utils/hashing.py`) but not yet wired into `resume_service.py`.
- No rate limiting implemented yet (section 32 lists this as required).
- `matching_service.py`'s project/certification scoring is presence-based
  only (has-projects vs. doesn't) - not yet matched against JD-specific
  project relevance the way skills/experience are.
- Semantic scoring has never been exercised with a REAL embedding model
  end-to-end (only synthetic test vectors) - the rescaling constants in
  `semantic_matcher.py` (`0.15`/`0.65`) are a reasonable starting point for
  typical embedding-model cosine similarity distributions, but should be
  recalibrated once real embeddings are flowing, ideally against the
  evaluation dataset planned for Phase 10.
- No integration/API-level test suite yet (httpx AsyncClient + test DB) -
  the 51 passing tests are all unit-level (pure functions + mocked LLM).
  The live curl-based verification this session covered that ground
  manually; it should become an automated `tests/integration/` suite next.
